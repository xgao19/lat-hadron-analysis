# 给数据科学学生的项目说明

## 这是什么项目

这个仓库用于分析格点 QCD（lattice QCD）数值模拟产生的数据。你不需要把它理解成一门高深的理论物理课，更适合把它看成一条“科学数据分析流水线”：输入是带噪声的数值数据，输出是带误差估计的物理量、拟合结果、图表和汇总文件。

从工程角度看，这个项目做的事情与很多数据科学项目类似：读入数据、做预处理、选择分析参数、运行拟合、生成结果、保存元数据，并尽量让整个过程可复现。

## 这里处理什么数据

仓库目前重点处理的一类数据是 two-point correlator（两点关联函数）。如果你没有物理背景，可以先把它理解成：

- 一组随“时间片”变化的数值序列
- 每个时间点都有统计噪声
- 通常不只一条，而是很多 bootstrap / resampling 样本
- 目标不是做预测，而是从噪声中稳定提取几个关键参数

直觉上，它有点像“带误差条的时间序列拟合问题”，只是这些序列来自物理模拟。

## 一个具体例子：2pt correlator 的 N-state fit

仓库里的一个典型程序是 two-point correlator 的 N-state fit。对数据科学背景的人来说，可以把它理解成：

- 输入是一批重采样后的带噪声时间序列
- 对每条时间序列做同一种非线性拟合
- 最后把所有拟合结果汇总成参数估计和统计误差

如果用很直观的方式表示，输入数据在内存里可以想成一个数组：

- `shape = [Nsamples, Nt]`
- 例如 `[800, 64]`
- 这里的意思是：有 800 个 bootstrap samples，每个 sample 都是一条长度为 64 的时间序列

这里的一个 bootstrap sample，可以简单理解成：从原始统计样本重新抽样后得到的一条“可用于重复分析的 correlator 曲线”。它不是完全新的实验，而是用来估计统计波动的一份重采样副本。于是，800 个 sample 就相当于“把同一个分析过程重复做 800 次，看结果如何波动”。

程序通常会先读取配置和数据，然后做一些标准预处理，例如：

- 按时间方向做 fold，把对称信息合并
- 做 binning，减弱相邻样本相关性
- 生成或读取 bootstrap 样本
- 选定拟合使用的时间区间

举一个只用于说明的玩具例子：假设某次拟合只使用 `t = 6, ..., 15` 这 10 个时间片。那么程序会对每个 bootstrap sample，取出这一段数据，去拟合同一个模型。

这个模型可以简单理解为“若干个指数衰减项之和”，例如

`C(t) = A0 exp(-E0 t) + A1 exp(-E1 t) + ...`

这里你不必在意它为什么长这样，只需要知道：

- `E0, E1, ...` 是要提取的能量参数
- `A0, A1, ...` 是对应的振幅参数
- `N-state` 的意思就是保留几个这样的指数项

因此，一次 2-state fit，本质上就是在一条时间序列上寻找一组参数，例如 `A0, A1, E0, E1`，让模型曲线尽量贴近数据。

这里的“拟合”不是随便画一条曲线，而是在解一个非线性优化问题。直观地说，它会在选定的时间范围内，最小化“模型值和数据值之间的不匹配”。常见写法是带权重的平方误差，也就是 least-squares / chi-square 一类目标：某个时间点误差越大、或者统计不确定度越小，它在目标函数里的权重就越明显。

所以，从计算角度看，这个流程很像：

1. 取第 `i` 个 bootstrap sample 的一段时间序列。
2. 给定初始参数，调用非线性优化器。
3. 最小化一类加权残差平方和。
4. 得到这一条 sample 的最佳拟合参数和拟合质量指标。

一次单独拟合的输出通常包括：

- 一组参数，如 `E0, E1, ...` 和 `A0, A1, ...`
- 拟合是否成功收敛
- `chi2/dof`、`p-value` 之类的拟合质量指标
- 该时间区间下的结果记录

然后，代码会对很多 bootstrap samples 重复这个过程。也就是说，它不是只得到一个 `E0`，而是得到一批 `E0`；不是只得到一个 `A0`，而是得到一批 `A0`。最后再对这些参数分布做汇总：

- 用参数分布的中心位置作为 central value
- 用参数分布的离散程度作为 statistical uncertainty

于是，最终输出就不只是“一个最优参数”，而是“参数估计值 + 统计误差 + 拟合质量 + 结果表格 + 图”。从数据科学角度，你完全可以把它看成：对许多重采样时间序列重复执行同一个受约束拟合流程，再对参数分布做统计汇总。

## 你应该重点关注什么

如果你以数据科学 / AI-agent / 工程支持的角色参与，这些方向最有价值：

- 改进 notebook 工作流，让用户更容易交互式运行分析
- 改进 config 设计、参数校验和报错信息
- 做自动化，例如批量运行、结果归档、日志整理、失败重试
- 组织输出文件、元数据、结果摘要和目录结构
- 帮助生成标准化报告、图表说明和结果总结
- 为常见任务做更清晰的 CLI、界面或模板
- 构建 AI agent，帮助用户选择流程、检查输入、解释输出

一句话说，你最适合做“让分析更易用、更稳健、更可复现”的部分。

## 不要随意改动什么

下面这些内容带有明确的科学含义，不建议在没有和物理负责人确认前随意修改：

- 核心拟合公式和模型形式
- state 的定义与参数含义
- 拟合区间选择逻辑中带科学判断的部分
- bootstrap / 误差处理方式中会影响最终科学结果的部分
- 结果文件里代表物理结论的关键字段含义

简单说：你可以优化“怎么运行、怎么检查、怎么展示”，但不要悄悄改变“算的是什么”。

## AI agent 在这个仓库里应该做什么

一个合适的 AI agent 应该偏向助手角色，而不是研究者角色。它适合做：

- 帮用户选择合适的 workflow（脚本、notebook、模板）
- 帮忙填写、检查和解释配置项
- 生成 notebook 模板或分析草稿
- 检测常见输入错误、缺失文件、路径问题、参数冲突
- 汇总输出结果，生成简洁的人类可读说明
- 帮助组织分析步骤、记录运行上下文和元数据

## AI agent 不应该做什么

- 不要发明新的物理方法或替换现有科学模型
- 不要在未经确认时修改科学假设
- 不要把“拟合跑通了”当成“科学上就是对的”
- 不要替代物理研究者对结果有效性的判断

AI agent 可以帮助提高效率，但科学有效性仍然需要由懂物理的人负责。

## 最后一句协作建议

如果你在这个项目里工作，可以把自己理解为“分析基础设施和用户体验的建设者”。目标不是重新设计物理，而是让现有分析流程更清楚、更稳、更自动化、更容易被别人正确使用。只要涉及模型、拟合策略、误差定义或物理解释，请先和项目负责人确认。
